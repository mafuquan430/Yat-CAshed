# 空类标定：把"我们自己的记账"摘掉，比值会降吗（2026-11-21）

## 问题

三配置消融告诉我们：主口径 1.81 倍里，选核只占 5%，其余 72% 花在"任务进了这个调度类"
之后的路径上。这 72% 到底是**我们自己的记账**（历史表、CRP、就绪池、计数器），还是
**"经过这个类"本身**（回调分发、入队出队、运行队列维护）？

这决定了路线 A′（减记账、减重复取锁）值不值得做：如果 72% 主要是记账，A′ 有明确靶子；
如果不是，A′ 就是把力气花在噪声上。

## 做法

在 `yat_casched.c` 里加一个只在命令行生效的开关 `yatnull=1`，开启后：

| 钩子 | 正常行为 | 标定模式 |
|---|---|---|
| `select_task_rq` | CRP 打分、查历史表、挑核 | 直接返回上一次的核（`task_cpu`），不算任何东西 |
| `task_tick` | 更新历史表、维护时间片 | 只 `update_curr`，随即返回 |
| `balance` | 扫就绪池、跨核分配 | 立即返回，不做迁移 |
| 入队/出队 | 红黑树 + 计数器 | **保持不变**（否则任务跑不起来） |

改动见 `null-mode.diff`（74 行，实验后已从工作树回退，内核重新编回正常版本 #22）。

负载与 #20 完全相同：8 任务、2M 迭代、200 µs 睡眠、可跨核；每轮先 CFS 后 Yat 配对，
比值 ρ = Yat / CFS；5 次重复。

## 结果

| 配置 | 中位数 | 最小 | 最大 |
|---|---|---|---|
| 正常实现（#20） | 1.812 | 1.756 | 2.131 |
| **空类标定（yatnull=1）** | **1.916** | 1.521 | 2.381 |

单轮 ρ：2.367、1.714、1.916、2.381、1.521。

## 怎么读

**摘掉记账没有让比值下降，反而略升且在噪声内抖动。** 三条推论：

1. **1.8 倍的主体不是我们的记账。** 历史表、CRP、计数器、就绪池这些东西加起来在噪声量级，
   这解释了为什么 `shared` 组（回调完全不进）仍有 1.72 倍——那 72% 属于"任务必须经过这个类"
   这条路径本身。
2. **放置逻辑在替自己还债。** 标定模式同时关掉了均衡，任务只能留在上一次的核上，并行度下降；
   比值从 1.81 变成 1.92（约 6%），说明我们的均衡在拿回一部分它自己花掉的钱。
3. **A′ 的预期收益有限。** 若目标是"减记账/减锁"，按本实验，可摘的部分不大；真正的杠杆在
   **放置质量与迁移策略**，不在表结构。

## 局限（必须一起报）

- 本实验把"记账"和"均衡"一起摘掉了，二者的效应混在一起，**无法单独归因**；
- 要干净地分离，需要让一个空调度类**复用 CFS 的选核**（`select_task_rq_fair` 在 fair.c 里是
  static，需要额外改造），预估一天工作量；
- 5 次重复、QEMU/TCG，噪声 20%–30%，只能支撑"没有下降"这样的方向性判断，不能支撑精确差值。
