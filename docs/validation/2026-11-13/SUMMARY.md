## 关于证据等级的说明

本文件记录两类材料，**证据等级不同**：

- **第 10 节（内核实测）**：本文的证据链。QEMU 上的真实内核，三组配置各重复 5 次，报中位数与全距。
- **第 3--5 节（模拟器）**：**前期工作**，不构成算法证据。模拟器的执行时间与命中判定都由自建模型
  给出，口径稍变结论就翻转（同一批数据在三套口径下分别是 11.66%、−0.95%、−3.52%）。保留这些记录
  是为了让"哪一版对、差在哪"可被第三方独立验证，而不是为了支持任何性能主张。

## 0. 结论摘要

1. **归档数字可逐字节复现**：旧口径（`--legacy-wfd-state`）下 5 个种子的 CSV 与 `2026-10-24/`
   完全一致（sha256 相同），说明代码与当时同源。
2. **但旧口径本身高估了算法**：WFD 静态负载跨用例残留，把 v2 从 −3.524% 抬到 −0.954%，
   把 v3 从 +0.988% 抬到 +3.385%——整张表一起抬高约 2.5 个百分点。本轮已把"每用例复位"
   改成主实验默认。
3. **宣传的 11.66% / +30.21 pp / 96% 不可复现**，来源是两套模型口径，已从 README 删除。
4. **把历史接回决策能拿到确定收益**：`CacheAware_v3`（α=0.5）默认口径 +0.988% Makespan、
   +6.788 pp 命中率、58.4% 胜率，区间均不含零。
5. **两个独立入口交叉验证一致**：主实验 `AlgorithmComparisonExperiment --allocator=v3` 与
   三算法对照 `AjlrLiteExperiment` 得到相同的 +0.988% / +6.79 pp。
6. **内核调度路径确实被触发**（接管率 98.5%），代价是 CFS 的 1.8–2.3 倍；对照实验把代价
   定位在唤醒路径的回调，而不是 AJLR 选核。
7. **修掉一个被 lockdep 实证的锁反序**：镜像 #19 复跑两组对照，同类告警 0 次。

## 4. 基线状态泄漏的机理

`WFD.PROCESSOR_LOADS` 是 `static`，旧入口只在每个种子开始时 `resetLoads()`；`CacheAware_v2`
每用例都 `resetState()`。于是同一批 100 个用例里，第 $i$ 个用例的 WFD 继承了前 $i-1$ 个用例
累积的负载偏置。证据有两条：

- 打开开关时 v2 的逐种子值与归档完全一致，关掉后变成 −3.524%；
- 命中率差几乎不受口径影响（v3：+6.36 vs +6.79 pp）。命中率由缓存模型按实际执行序列统计，
  与"WFD 是否记得上一个用例"无关——说明差异来自基线时序，不是缓存模型抖动。

## 6. 内核实测

同一负载：8 任务 × 2,000,000 次迭代 = 16,000,000 工作单元（两策略完成量相同）。

| 配置 | 唤醒 | 亲和性 | select_calls | place_hit | Yat/CFS | 备注 |
|---|---|---|---|---|---|---|
| 镜像 #18 | 200 µs | none | 256 | 937 | 2.295 | 主实验口径 |
| 镜像 #19 (1) | 200 µs | none | 467 | 981 | 2.281 | 锁修复后 |
| 镜像 #19 (2) | 200 µs | none | — | — | 1.901 | 重复 |
| 镜像 #19 (3) | 200 µs | none | — | — | 1.779 | 重复 |
| 镜像 #19 | 200 µs | shared | 0 | 0 | 1.754 | 回调不被调用 |
| 镜像 #18 | 200 µs | shared | 0 | 0 | 1.986 | 同上 |
| 镜像 #18 | 0 | none | 0 | 0 | 0.827 | 无唤醒对照 |

镜像 #19 主配置计数器：`ttwu_ok=512`，`select_calls=467`，`select_sticky_idle=208`（44.5%），
`select_decided=259`，`jobs_placed=259`，`place_hit=981`、`miss=0`、`pending=15`，接管率 98.5%；
`enq_calls=475`、`enq_cpus_allowed=1900`（平均可运行核数 4.0）；`balance_runs=743`。

三条站得住的结论：
1. 决策链路通了（回调被调用、决策落地、接管率 98%+）；
2. 代价不是"选核"带来的——单核 pin 时回调一次都没被调用，仍然慢 1.75–1.99 倍；
3. 去掉唤醒时 Yat 反而快 17%，代价随唤醒次数增长，落在 `balance`/`enq`/`deq` 上
   （`balance_runs=743` > 唤醒 512）。

**不做因果过度解读**：TCG 下同一配置三次运行 1.78/1.90/2.28，波动 28%。#18 与 #19 的差异
落在噪声内，所以"锁修复提升了性能"不成立；能说的是"锁修复消除了告警，且没有性能回归"。

## 10. 内核实测（重复测量，证据链）

脚本：`scripts/run_kernel_repeats.sh --repeats 5`；原始数据：`kernel/repeat/`（15 次运行，
每轮两次独立启动 CFS 与 Yat）。负载：8 任务 × 2,000,000 迭代 = 16,000,000 工作单元，
`--sleep-us 200`（512 次唤醒），`--affinity none`。

| 配置 | n | 中位数 ρ | 全距 | 说明 |
|---|---|---|---|---|
| none + 200 µs（主口径） | 5 | **2.002** | [1.612, 2.506] | 完整链路 |
| shared + 200 µs（回调不被调用） | 5 | **1.702** | [1.550, 2.395] | 只有"进入调度类"的代价 |
| none + 无唤醒 | 5 | **1.105** | [0.731, 1.363] | 跨 1，基础路径无代价 |

归因（三条一起读才有意义）：

1. **主口径慢一倍**（2.00×），当前实现不具备可用性。
2. **回调关掉仍慢 1.70×**（`select_calls=0`，AJLR 一次都不跑）→ 主体代价不是选核，
   而是"唤醒时进入这个调度类"的路径。
3. **没有唤醒时两者没有可分辨差异**（1.10，全距跨 1）→ 代价随唤醒次数增长，
   基础调度（时间片、pick、上下文切换）不构成开销。

选核的边际代价 = 2.00/1.70 ≈ 1.18（约 18%）。计数器支持同一指向：`balance_runs=757`
而唤醒仅 512 次，几乎每个调度点都在重扫就绪池。

> 早期单次测量给出的 0.827（"无唤醒快 17%"）**不成立**——5 次重复的中位数是 1.105、全距跨 1。
> 这正是要重复测量的原因：TCG 下同配置波动可达 28%。
